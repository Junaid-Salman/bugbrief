BugBrief Privacy Policy

Effective date: 2026-10-20. Last updated: 2026-10-20.

BugBrief is a free, open-source Chrome extension. It packages a broken web page (console errors, failed requests, one element and a screenshot) into one Markdown report that you can paste into an AI coding agent or send to a teammate. This policy says what it reads, where that data lives and what it never does.

In short

  • BugBrief reads data from the tab you choose to record, and only after you click Start recording.
  • All of it stays on your device. It is never sent anywhere. BugBrief has no server and no account.
  • It is not sold, not used for advertising, not shared and not read by any person.
  • BugBrief masks secrets it recognizes, but it can miss others and it does not mask the screenshot. Read the report before you share it.

What BugBrief reads

From the tab you record, BugBrief reads:

  • the page content and the element you pick, and a screenshot of that element;
  • the addresses (URLs) the page uses, and the contents of its requests and responses;
  • console errors and messages.

That can include personal data, sign-in tokens, form values and other sensitive information that the page shows or sends, for example names, email addresses, authentication information, financial, health or private messages if they appear on the page you record. BugBrief does not look for any of these on purpose. It reads what the page holds so that the report can explain the bug.

Where the data lives

  • While you record, the events are kept in memory and in chrome.storage.session. Chrome clears that storage when the browser closes.
  • The picked element and its screenshot are kept there too, and so is a draft of the note you type.
  • One setting is kept in chrome.storage.local: whether you have seen the first-run notice.
  • The data is removed when you click Clear, start a new recording, or close the browser.

What BugBrief does with the data

  • It builds the report you ask for. Nothing else.
  • The report goes to your clipboard when you click Copy, and to files when you click Download. You choose where to paste or save it. What you do with it afterwards is up to you.
  • BugBrief makes no network requests of its own, includes no analytics or tracking, loads no remote code and has no third-party services.

Redaction

BugBrief masks secrets it recognizes, such as tokens, keys, passwords and email addresses, before the report is shown, copied or saved. Redaction is pattern based. It can miss others, and keys with no recognizable name or format may not be masked, for example some AI provider keys. The screenshot is not masked at all. Read the report and look at the screenshot before you share them.

Permissions

BugBrief asks for debugger (to read console errors and failed requests from the tab you record, after you click Start recording), activeTab and scripting (to let you pick an element and to capture it), storage (the in-session buffer and the first-run setting) and downloads (to save the files when you click Download). It asks for no access to all websites.

Limited Use

The use of information BugBrief receives through Chrome extension APIs adheres to the Chrome Web Store User Data Policy, including the Limited Use requirements. The data is used only to build the report you ask for. It is not transferred to anyone, not used for advertising or for credit decisions, and no person reads it.

Children

BugBrief is a developer tool and is not directed at children.

Changes to this policy

If this policy changes, the new version replaces this page and the effective date above changes. The history is public in the project's repository.

Contact

Questions, or a secret that reached a report: please open an issue and describe where it appeared, but not the secret itself. The source code is at github.com/Junaid-Salman/bugbrief under the MIT license.
